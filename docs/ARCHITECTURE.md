# Архитектура HackAlem AI

## Формат репозитория

Проект развивается как монорепозиторий с двумя независимыми приложениями:

```text
backend/   NestJS API, подбор подрядчиков и интеграция с OpenAI
frontend/  Next.js web-интерфейс
```

На первом этапе источником данных остаётся CSV. База данных, очередь задач и векторная база не
добавляются, пока для них не появится реальная потребность.

## Backend

Базовый стек:

- Node.js LTS, TypeScript и NestJS;
- npm как единый package manager;
- REST API с префиксом `/api/v1`;
- `@nestjs/config` для переменных окружения;
- `class-validator` и `class-transformer` для входных DTO;
- `@nestjs/swagger` для OpenAPI и интерактивной документации;
- `csv-parse` для загрузки исходного датасета;
- официальный пакет `openai` и Responses API для ИИ-слоя;
- Zod для проверки Structured Outputs от модели;
- `nestjs-pino` и `pino-pretty` для структурированных логов;
- `helmet`, CORS и `@nestjs/throttler` для базовой защиты API;
- Jest и Supertest для unit- и e2e-тестов;
- ESLint и Prettier для качества кода.

API-ключ хранится только на backend в `OPENAI_API_KEY`. В репозиторий попадает лишь
`.env.example` без значения ключа. Frontend никогда не обращается к OpenAI напрямую.

### Backend-модули

```text
src/
  config/             проверка конфигурации и переменных окружения
  health/             GET /api/v1/health
  contractors/        загрузка CSV и доступ к нормализованным профилям
  recommendations/    POST /api/v1/recommendations и сценарий подбора
  matching/           обязательные фильтры и детерминированный fallback-scoring
  ai/                 OpenAI client, prompts, schema и обработка ошибок API
  common/             общие фильтры, ошибки, логирование и типы
```

### Поток рекомендации

1. DTO проверяет город, дату, категорию, бюджет и необязательные параметры.
2. `contractors` получает кандидатов из нормализованного CSV.
3. `matching` применяет жёсткие ограничения: город, категория, занятость, бюджет, формат,
   а также язык и длительность, если они переданы.
4. `ai` получает только допустимых кандидатов, оценивает смысловое соответствие запросу и
   формирует персональные объяснения.
5. Ответ модели проходит Zod-проверку и сверку идентификаторов с исходным списком кандидатов.
6. Сервис стабильно сортирует результат и возвращает максимум три карточки.
7. При ошибке или таймауте OpenAI включается детерминированный fallback, поэтому endpoint не
   перестаёт работать.

ИИ не имеет права возвращать занятого подрядчика, менять цену или придумывать отсутствующие поля.
Жёсткие бизнес-правила проверяются обычным кодом до и после вызова модели.

### Контракт и воспроизводимость

Точный контракт и контрольные числа: `docs/API-CONTRACT.md`. Цена сравнивается с бюджетом
за мероприятие и отображается как «от». `max_hours=null` пропускает фильтр длительности.
Структурированные поля CSV определяют формат и языки даже при расхождении со свободным
описанием. Календарь известен только с 23.09.2026 по 31.12.2026; другие даты отклоняются.

Стабильная сортировка сама по себе не делает ответы LLM повторяемыми. Первый результат
запроса фиксируется в JSON-снимке на диске (включая fallback), с ключом из параметров,
хэша CSV, модели, версии алгоритма/промпта и включённости ИИ. Параллельные одинаковые
запросы используют одно вычисление. Docker сохраняет снимки в named volume. Это кэш
ответов, а CSV остаётся единственным источником профилей; БД и Redis не используются.
Поддерживаемая топология MVP: один backend-процесс. Изменение версии/данных/модели или
удаление кэша означает новый набор результатов, что нужно учитывать при сравнении демо.

### Запуск

В корне расположен `docker-compose.yml`. Backend собирается с контекстом корня, чтобы
воспроизводимо включить исходный CSV в образ, frontend имеет собственный build context.
Next.js использует server-only `BACKEND_URL` и проксирует `/api/v1/*`; секрет OpenAI
остаётся исключительно у NestJS. API слушает 3001, интерфейс 3000, Swagger `/api/docs`.

## Frontend

Базовый стек:

- Next.js с App Router, React и TypeScript;
- Tailwind CSS для стилей;
- shadcn/ui на базе Radix UI для доступных компонентов;
- Lucide React для иконок;
- React Hook Form, Zod и `@hookform/resolvers` для формы;
- TanStack Query для запроса рекомендаций и состояний загрузки/ошибки;
- Sonner для коротких уведомлений;
- Vitest и Testing Library для компонентов;
- Playwright для основного пользовательского e2e-сценария;
- ESLint и Prettier для качества кода.

Redux на старте не нужен: состояние состоит из формы, результата запроса и небольших UI-состояний.
Клиент работает только с NestJS API. Контракт ответа будет типизирован по OpenAPI-схеме backend.

## Конечный продукт

Пользователь открывает Next.js-страницу, задаёт параметры мероприятия и получает до трёх карточек
подрядчиков с понятными ИИ-объяснениями. NestJS остаётся отдельным API и также предоставляет
Swagger для разработки и демонстрации. Существующий `hackathon dataset preview.html` остаётся
внутренним просмотрщиком исходных данных и не является пользовательским frontend.

## Порядок реализации

1. Развернуть NestJS в `backend/` и реализовать загрузку CSV, фильтры и тесты.
2. Подключить OpenAI через Responses API и Structured Outputs, затем добавить fallback.
3. Зафиксировать OpenAPI-контракт и демо-сценарии.
4. Развернуть Next.js в `frontend/` и подключить форму к готовому API.
5. Добавить e2e-тест и подготовить развёртывание.
