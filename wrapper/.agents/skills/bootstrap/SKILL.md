# bootstrap

Один проход. Максимум 3 вопроса — в конце, одним сообщением. Пишется `AGENTS.md`; память пишется
только если в текущей среде доступен MCP-сервер Serena.

**Не задача этого скилла**: писать код приложения, ставить зависимости без спроса, сочинять
роадмапы и тикеты, чинить найденные красные тесты. Обёртка настраивается — проект не начинается.

## Что посмотреть сначала

- Корень репозитория: `rg --files -uu | head` или ближайший аналог.
- Манифесты и конфиги: `package.json`, `pubspec.yaml`, lock-файлы, `nest-cli.json`, `next.config.*`, `vite.config.*`, `analysis_options.yaml`, `.fvmrc`, `turbo.json`, `Makefile`, `docker-compose*`.
- Уже существующая настройка: `AGENTS.md`, `.codex/`, `.agents/skills/`, `.serena/memories/`.
- История: `git log --oneline -8`, если это git-репозиторий.

## 0. Развилка — что здесь уже есть

Совпало несколько развилок — действуют все их ограничения сразу, и запрет сильнее предписания.

- `AGENTS.md` есть, но строки `codex-wrapper:unbootstrapped` в нём нет — он пользовательский. Не трогать ни на каком шаге: шаг 5 только показывает предлагаемый текст в чате, а записывает его лишь по явному разрешению.
- Памяти в `.serena/memories/` уже есть — проект живой. Выполнить шаги 2–5; из шага 6 завести только `MEMORY` — индекс по уже лежащим там файлам, их содержимое не читать и не править.
- Serena MCP недоступна — пропустить запись памяти и явно сказать, что долговременная память не активирована.

Дальше «пустой репозиторий» значит: нет манифеста (`package.json`, `pubspec.yaml`) и нет исходников.
Файлы самой обёртки — `AGENTS.md`, `.codex/`, `.agents/` — за наполнение не считаются.

## 1. Прочитать ТЗ — вопросов пока не задавать

Источник — аргумент скилла, присланное сообщение или названный файл. Достать в голову, не в файл:
что строим и для кого одним предложением; жёсткие ограничения; обязательные технологии;
интеграции; куда деплоим; что явно вне задачи; доменные существительные дословно на языке ТЗ.
Переводить нельзя: этими же словами будут названы сущности в коде и базе. Пробелы — в список
кандидатов на вопросы, из которых до шага 7 доживут максимум три.

ТЗ нет, но код есть — это онбординг на чужой проект: `project-brief` собирается из кода.

## 2. Определить стек

По выводу выше, первое совпадение выигрывает:

| признак | стек | файл правил |
|---|---|---|
| `pubspec.yaml` | flutter | `.codex/rules/flutter.md` |
| зависимость `@nestjs/core` | nest | `.codex/rules/nest.md` |
| зависимость `next` или `next.config.*` | next | `.codex/rules/react.md` |
| `react` + `vite.config.*` | react-vite | `.codex/rules/react.md` |
| пустой репозиторий | из ТЗ, не сказано — вопрос №1 | — |

`nest.md` и `react.md` оба относятся к TypeScript, поэтому лишний из этих двух удалить — иначе
агент будет читать правила чужого стека. `flutter.md` оставить, если в репозитории есть `.dart`.
Если есть Flutter и фронтенд рядом, оставить оба соответствующих файла.

## 3. Выверить правила стека под проект

Прочитать файл своего стека. Каждую стартовую строку сверить с тем, что видно в репозитории, и
удалить неверные: нет локализации — уйдёт правило про строковые литералы, нет `.fvmrc` или не
установлен `fvm` — уйдёт правило про `fvm`, нет слоёв — уйдёт правило про направление импортов.
Пустой репозиторий — оставить как есть.

## 4. Проверить команды — шаг, который нельзя пропустить

Не записывать команду, которую не запускал.

Сначала перечислить, а не угадать. Для JS/TS перечень — секция `scripts` из `package.json`. Для
Flutter перечнем считаются штатные команды: `flutter pub get`, `flutter analyze`,
`dart format --output=none --set-exit-if-changed .`, `flutter test`.

Префикс `fvm` ставится, только когда есть и `.fvmrc`, и сам бинарь (`command -v fvm`).

Запускать только то, что напечаталось, по одной, в порядке: типы → линт → сборка → тесты.
Таймаут: 120 000 мс на типы и линт, 600 000 мс на сборку и тесты.

Никогда не запускать: `dev`, `start`, `serve`, `watch`, `storybook`; `migrate`, `seed`,
`db:push`, `deploy`, `release`; сборки артефактов магазинов (`build:apk`, `build:ipa`,
`build:bundle`) и всё, где есть `--export-method`, `xcarchive`, `open `. Из нескольких сборок
запускать максимум одну, самую дешёвую.

Классифицировать каждую:

- РАБОТАЕТ — настоящий инструмент отработал, код возврата не важен.
- ПАДАЕТ — отработала, но с реальными ошибками. Записать число/суть ошибок.
- НУЖНЫ СЕРВИСЫ — `ECONNREFUSED`, docker. Записать как `команда  # нужен: docker compose up -d`.
- ТАЙМАУТ — не уложилась. Записать `# не проверено: таймаут <n> мин`, но не как падающую.
- НЕТ ТАКОЙ — код 127, `Missing script`, `command not found`. В `AGENTS.md` не попадает.

Пустой репозиторий — проверять нечего: над блоком команд поставить видимую строку
`НЕ ПРОВЕРЕНО (репозиторий был пуст) — перепроверить после первой задачи:`.

## 5. Написать AGENTS.md

Взять `.agents/skills/bootstrap/agents-md.template` и заполнить. Потолок — 60 строк, проверить.
Не влезает: первым режется «Нерушимое», прозаические абзацы удаляются всегда. Больше ничего не
создавать: ни `docs/`, ни roadmap, ни ADR.

## 6. Serena

Если доступен MCP-сервер Serena, активировать проект на абсолютный путь репозитория. Если Serena
предложит своё онбординг-обследование — отказаться.

Завести сейчас, а не собраться завести потом:

| память | что внутри |
|---|---|
| `project-brief` | сжатое ТЗ: что и для кого, жёсткие ограничения, что вне задачи, глоссарий дословно, открытые вопросы |
| `stack-and-commands` | стек, менеджер пакетов по lock-файлу, версии, каждая команда со своим статусом из шага 4 |
| `MEMORY` | индекс: по строке на память, включая те, что лежали здесь до обёртки |

`architecture`, `conventions`, `decisions` заводит learn, когда появится наблюдённое знание.
На пустом репозитории писать в них нечего.

## 7. Спросить — не больше трёх, пачкой, один раз

Вопрос задаётся, только если на него не отвечает репозиторий, на него не отвечает ТЗ, он меняет
то, что будет сделано в первой задаче, и у него нет защитимого дефолта. Порядок: объём →
безопасность и приватность → UX → техника.

## 8. Отчёт, пять строк

```
стек:     <id> → правила .codex/rules/<файл>, выверено, убрано строк: <n>
команды:  <n> работает, <n> падает (<детали>), <n> таймаут, <n> нет
записано: AGENTS.md (<n> строк)
память:   project-brief, stack-and-commands, MEMORY / Serena недоступна
дальше:   <первая конкретная задача из ТЗ>
```

Отчёт обязан описывать то, что произошло на самом деле.
