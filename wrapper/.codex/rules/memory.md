# Память проекта

Одно хранилище — Serena (`.serena/memories/`), если MCP-сервер Serena доступен в текущей среде.
Читать и писать только её тулзами (`read_memory`, `write_memory`, `list_memories`,
`delete_memory`), не через `cat`/`grep`. Индекс называется `MEMORY` — с него начинается любое
обращение к памяти.

Если Serena не подключена, не имитируй память файлами: скажи, что долговременная память в этом
проекте не активирована, и работай от `AGENTS.md` плюс кода.

## Что записывать

- Неочевидный инвариант, принятое решение и его причина, ловушка, граница между системами, поведение внешнего сервиса.
- Тест на допуск: **это можно узнать, прочитав код, git log или README?** Тогда не записывать.
- Не записывать никогда: структуру кода, списки файлов, пересказ диффа, историю «как мы это чинили», то, что уже есть в `AGENTS.md`.

## Как записывать

- Сначала `read_memory("MEMORY")`. Есть релевантная память — обновить её. Две памяти на одну тему — это баг.
- Имя — kebab-case по паттерну или архитектуре (`auth-flow`, `payment-webhooks`), не по эпизоду. Без суффиксов `-fix`, `-v2`, `-migration`, `-perf`.
- Настоящее время, текущее состояние: «использует X», а не «убрали Y, добавили X». Даты только абсолютные.
- Доменные термины — на языке ТЗ. Перевод гарантирует расхождение с кодом и базой.
- Строка в `MEMORY` пишется в том же ходу: `- [Заголовок](имя.md) — за чем сюда заглядывать`.
- Память, которую уже не пролистать глазами, разрезать: карточка со ссылкой на `<имя>-details`.
- Устаревшую — удалить. Больше восьми памятей — слить, прежде чем заводить девятую.
