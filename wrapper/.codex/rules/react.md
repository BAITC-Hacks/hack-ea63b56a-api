# React / Next.js

Прочитай этот файл перед правками в `*.tsx`, `*.jsx` или фронтенд-части `*.ts`.
Стартовые строки ниже — типовые ловушки. Неверное для проекта удалить на bootstrap.

- Весь HTTP — через единственный api-клиент проекта. Голый `fetch`/`axios.create` в компоненте запрещён.
- Серверное состояние — через слой запросов/стор проекта. Не писать руками `useEffect` + `useState` для загрузки.
- Ни одного цветового литерала (`#fff`, `rgba()`, `white`): только токен темы или CSS-переменная проекта. В тёмной теме литерал становится невидимым текстом.
- Поля формы — через API формовой библиотеки проекта, не через локальный `useState` + `onChange`.
- Диалог, селект, таблицу, тост брать из существующих примитивов проекта, а не писать заново.
- Новая страница регистрируется в единственном живом конфиге роутов/меню. Найти его через `rg`, а не заводить второй.
- Импорты идут только вниз по слоям (pages → features → entities → shared). Вверх — никогда.
- Повторяющиеся наборы опций — enum плюс карта лейблов, не инлайновые строки в месте вызова.
- У каждого асинхронного действия видимое состояние загрузки и видимая ошибка.

## Только Next.js

- По умолчанию серверные компоненты. `'use client'` — только ради хуков, состояния или браузерных API.
- Клиентский стор не импортируется в серверный компонент.
- Модуль данных обязан работать на обеих ветках — серверной (куки/заголовки запроса) и клиентской. Проверять обе.
