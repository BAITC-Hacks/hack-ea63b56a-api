# Flutter

Прочитай этот файл перед правками в `*.dart`. Стартовые строки ниже — типовые ловушки.
Неверное для проекта удалить на bootstrap.

- Есть `.fvmrc` — каждую команду `flutter`/`dart` запускать с префиксом `fvm`. Иначе соберётся не тот SDK.
- Готово = `flutter analyze` без ошибок И без предупреждений, затем `dart format .`, затем `flutter test`.
- Ни одной пользовательской строки литералом: ключи локализации, ключ сначала добавляется в базовую локаль.
- Проверка перед сдачей любой i18n-задачи: `rg "[А-Яа-я]" lib/ -g "*.dart"` не находит ничего вне файлов локалей.
- Один подход к состоянию на приложение — тот, что уже в `lib/`. Второй не заводить.
- Роуты, темы и регистрации зависимостей живут в своих единственных файлах регистрации, а не инлайном в виджете.
- Один HTTP-клиент на бэкенд, создаётся один раз и инжектится. Не создавать клиент внутри виджета или контроллера.
- Обновления между экранами — через общий event bus / стрим / сервис, а не колбэком из контроллера в контроллер.
- Ассет должен физически лежать на диске и быть объявлен в `pubspec.yaml` до того, как на него сошлются.
- После правки генерируемых моделей или роутов: `dart run build_runner build --delete-conflicting-outputs`.
- Пакет (в `lib/` нет `runApp`/`MaterialApp`) живёт по конвенциям хоста, а не приложения. Сначала понять, что перед тобой.
