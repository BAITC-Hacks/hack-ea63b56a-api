# NestJS

Прочитай этот файл перед правками в NestJS-коде. Стартовые строки ниже — типовые ловушки,
а не учебник по Nest. Неверное для проекта удалить на bootstrap.

- Не лезть в потроха чужого модуля или приложения — только через его опубликованный клиент/сервис.
- Входящий DTO — только валидаторы. Исходящий — каждое возвращаемое поле объявлено явно.
- Поле, которого нет в исходящем DTO, молча исчезает из ответа. Чинить в DTO, а не в запросе.
- `whitelist: true` так же молча режет поля, которых нет во входящем DTO, — правя схему, обнови все связанные DTO, включая вложенные.
- Имена очередей, джобов, событий и message-паттернов — из enum. Никогда строковый литерал.
- Общий код импортировать по алиасу из `tsconfig`, не относительным `../../`.
- Идентификаторы сравнивать строками, не по ссылке.
- Новая фича — одна папка: `{feature}.controller.ts` + `.service.ts` + `.module.ts` + `dto/`.
- Есть README модуля — прочитать перед правкой внутри и обновить в той же задаче.
- Тесты к новому коду не добавлять без запроса. Разовые скрипты — на TypeScript.
