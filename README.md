# Обёртка Codex

Лёгкая настройка Codex под NestJS, React+Vite, Next.js и Flutter. Внутри: короткий `AGENTS.md`,
правила в `.codex/rules/`, два скилла в `.agents/skills/` и проектная настройка Docs MCP для
официальной документации OpenAI.

Память проекта опционально держится в Serena. Если MCP-сервер Serena не подключён, обёртка всё
равно работает: Codex опирается на `AGENTS.md`, правила и код, но долговременные проектные факты
не записывает.

## Установка

```sh
./install.sh /путь/к/проекту
```

Скрипт ничего не перезаписывает. Если `AGENTS.md` или `.codex/config.toml` уже есть, он скажет,
что пропустил, и обёртка будет установлена не полностью: слейте руками или попросите Codex
выполнить bootstrap в целевом проекте.

После копирования перезапустите Codex в целевом проекте, чтобы он перечитал `AGENTS.md`,
проектный `.codex/config.toml` и скиллы.

## Первый промпт

Пришлите ТЗ проекта и попросите: «настрой проект». Bootstrap за один проход:

- определит стек;
- выверит стартовые правила под проект, удалив неверные;
- запустит безопасные команды типов, линта, сборки и тестов;
- запишет в `AGENTS.md` только команды, которые реально проверял;
- если доступна Serena, заведёт стартовые памяти;
- задаст не больше трёх вопросов пачкой.

## Что где

| Что | Где | Когда использовать |
|---|---|---|
| Карта проекта и команды | `AGENTS.md` | каждую сессию |
| Общие правила работы | `.codex/rules/core.md` | перед нетривиальной задачей |
| Правила памяти | `.codex/rules/memory.md` | перед записью проектной памяти |
| Правила стека | `.codex/rules/{nest,react,flutter}.md` | перед правками в соответствующем стеке |
| Настройка под проект | `.agents/skills/bootstrap/` | по просьбе «настрой проект» / bootstrap |
| Самоулучшение | `.agents/skills/learn/` | по просьбе «запомни», «ретро», learn |
| OpenAI Docs MCP | `.codex/config.toml` | для OpenAI API, Codex, ChatGPT и plugin-документации |

Лишние файлы правил bootstrap удаляет: `nest.md` и `react.md` оба цепляются за TypeScript, и
оставленный чужой файл будет мешать. Вернуть стартовый набор можно повторным запуском
`install.sh`.

## Чем это отличается от Claude-версии

- `CLAUDE.md` заменён на `AGENTS.md`: по официальной документации OpenAI Codex автоматически
подхватывает такие инструкции из проекта.
- `.claude/settings.json` и хуки Claude удалены. У Codex нет прямого аналога этих хуков в этом
шаблоне; напоминание про `learn` теперь живёт в правилах и `AGENTS.md`.
- `.claude/rules/` заменён на `.codex/rules/`.
- `.claude/skills/` заменён на `.agents/skills/`, а `AGENTS.md` явно маршрутизирует Codex к этим
процедурам.
- Настроен OpenAI Docs MCP через `.codex/config.toml`:

```toml
[mcp_servers.openaiDeveloperDocs]
url = "https://developers.openai.com/mcp"
```

## Как это себя улучшает

`learn` раскладывает урок ровно по одному адресу: факт о проекте → память Serena; нарушенный
инвариант → строка в `.codex/rules/`; то, что способен поймать парсер → правило линтера;
повторяющаяся процедура → предложение завести скилл; отвергнутый подход → `core.md`.

Всё сначала предлагается списком, молча не пишется ничего. Он же чистит: при превышении примерно
90 строк правил или восьми памятей запускается аудит, и его смысл — удалять.

## Чего намеренно нет

Нет Claude-only хуков `SessionStart` и `PostToolUse`, `autoMemoryEnabled`, разрешений
`mcp__serena__*` внутри settings-файла и команды `/context`. Это были особенности Claude Code, а
не переносимые настройки Codex.

Ещё нет: субагентов, цепочки команд-оркестраторов, `LEARNINGS.md`, автозапуска небезопасных
команд, деплоя или миграций.

## Обслуживание

Попросите Codex выполнить `learn audit` — он сольёт дубли, удалит противоречащее и выбросит
правила, чья причина исчезла из кода.
