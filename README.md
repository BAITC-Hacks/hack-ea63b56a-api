# Evently — умный подбор event-подрядчиков

Первый рабочий вариант сервиса для задачи HackAlem #79-lite. Пользователь описывает мероприятие
своими словами или задаёт параметры вручную, а система возвращает до трёх детерминированных
рекомендаций и объясняет каждую из них на фактах из каталога.

## Что реализовано

- AI-first интерфейс на Next.js с ручной формой как альтернативой;
- разбор русскоязычного запроса через OpenAI Responses API и Structured Outputs;
- NestJS API с валидацией DTO;
- фильтрация по городу, категории, занятости, формату, бюджету, длительности и языку;
- AI-объяснения TOP-3 на основе рассчитанных фактов;
- локальный fallback для разбора и объяснений при отсутствии ключа или ошибке API;
- стабильная сортировка: score → цена → id;
- максимум три карточки с индивидуальными объяснениями;
- отдельные состояния `matched`, `no_category_in_city`, `no_candidates_after_filters`;
- причины исключения и рассчитанные предложения по смягчению условий;
- заметная метка синтетического профиля;
- loading, error и 404 состояния;
- адаптивная вёрстка для desktop, tablet и mobile.

## Запуск

Требуется Node.js 22 или новее (локально проверено на Node.js 24).

```bash
npm install
npm run dev
```

После запуска:

- интерфейс: `http://localhost:3000`;
- API: `http://localhost:3001`;
- health check: `GET http://localhost:3001/health`.

Создайте локальный `.env` по примеру `.env.example` и добавьте API-ключ:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-6-luna
```

`.env` исключён из Git. Ключ используется только NestJS-сервером и никогда не передаётся в браузер.
Адрес API для интерфейса задаётся отдельно в `apps/web/.env.local` по примеру
`apps/web/.env.local.example`. Next.js читает окружение из своей папки. После изменения окружения
перезапустите серверы (для production — пересоберите интерфейс).
Без ключа приложение продолжает работать через детерминированный fallback и явно показывает этот
режим в интерфейсе.

## API

### `GET /recommendations/metadata`

Возвращает реальные города, категории, форматы и языки из CSV для формы.

### `POST /recommendations/parse`

```json
{
  "text": "Нужен ведущий в Алматы на корпоратив 15 октября. Бюджет до 900 000 ₸, на 5 часов, русский язык"
}
```

Извлекает параметры через OpenAI Structured Outputs и возвращает один полезный уточняющий вопрос,
если не хватает обязательных данных. При недоступности API автоматически используется локальный
эвристический парсер.

### `POST /recommendations`

```json
{
  "city": "Алматы",
  "date": "2026-10-15",
  "eventType": "корпоратив",
  "category": "Ведущий",
  "budgetKzt": 900000,
  "durationHours": 5,
  "language": "русский",
  "wishes": "современный стиль и интеллектуальный юмор"
}
```

## Проверка

```bash
npm run lint
npm test
npm run build
```

Unit-тесты покрывают занятую дату, отсутствие категории в городе, фильтрацию всех кандидатов и
детерминированный порядок с лимитом в три результата.

## Демо-сценарии

1. Алматы, `2026-10-15`, корпоратив, Ведущий, 900 000 ₸, 5 часов, русский.
2. Астана, редкая категория Флорист или Инструменталист — состояние малой выборки/отсутствия категории.
3. Алматы, Ведущий, бюджет 1 ₸ — содержательный пустой результат и предложение повысить бюджет.
4. Повторить первый запрос на `2026-12-20`, чтобы увидеть влияние плотной декабрьской занятости.

Фильтрация занятости, бюджета, формата, языка и длительности всегда выполняется обычным кодом.
OpenAI отвечает только за понимание свободного текста и индивидуальную формулировку объяснений.
