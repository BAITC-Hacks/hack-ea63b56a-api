# Сценарии подбора подрядчиков

Новые сценарии лежат в корневой папке `tests/` и запускаются вместе с существующими
backend-тестами. Файлы `*.spec.cjs` используют настоящие сервисы и синтетические
фикстуры; работающий сайт и сетевой доступ к AI для них не нужны. Исходный датасет
не изменяется. Отдельный `site-scenarios.mjs` проверяет запущенный сайт в Chromium.

Актуальный аудит: [AI-SCENARIOS-REPORT.md](AI-SCENARIOS-REPORT.md).
На `05be10f` backend: **75 PASS / 4 FAIL**. Три проверки показывают публикацию
неподтверждённых AI-утверждений; ещё одна обнаруживает карточку дороже бюджета,
которую новый код добавляет как альтернативу. На `f827a95` и `b27954f` падали только
три проверки AI-текста. Проверки не пропущены и не объявлены ожидаемо успешными;
общая команда backend возвращает ненулевой код, пока эти расхождения сохраняются.

Из корня проекта, с Node.js 22.13+:

```sh
npm --prefix backend ci
npm --prefix backend test
```

Только новые сценарии:

```sh
npm --prefix backend test -- --runTestsByPath ../tests/matching.spec.cjs
```

1. Один подрядчик не проходит одновременно по бюджету и языку. Обе причины
   учитываются, изменение только одного условия не даёт совпадения.
2. Один подрядчик подходит только по цене, другой — только по языку. Выдача пуста:
   все условия должны выполняться для одного профиля. Добавление подходящего
   по обоим условиям профиля даёт ровно его в допустимом наборе.

Это проверки фильтрации. HTTP-статусы, объяснения и интерфейс также проверяются
существующими наборами в `backend/test/` и `frontend/`.

## Проверка сценариев и ошибок ИИ

```sh
npm --prefix backend test -- --runTestsByPath ../tests/recommendation-scenarios.spec.cjs
node tests/site-scenarios.mjs
```

`recommendation-scenarios.spec.cjs` содержит 7 проверок полного пути от фильтров
до карточек и снимков результата:

- Один профиль не проходит сразу по дате, бюджету, формату, языку и часам;
  все пять причин объяснены, вызова OpenAI нет.
- Бюджет и часы ровно на границе проходят, превышение на 1 тенге или 0.01 часа — нет.
- ИИ перемешал четыре кандидата: оценки, имена и цитаты остаются у своих профилей;
  выдаётся правильный топ-3.
- Два параллельных запроса с разными языками и бюджетами завершаются в обратном
  порядке, но не смешивают результаты и сохранённые снимки.
- Выдуманная услуга, отсутствующий язык и обещание доступности в любой день
  не должны попадать в карточку — три регрессионные проверки выявленного дефекта.

`site-scenarios.mjs` требует установленный Chromium и работающий сайт на 3000
(другой адрес: `FRONTEND_URL`). Он сверяет три непустых имени карточек с реальным
API, проверяет восстановление после подставленного HTTP 503 и вывод HTML из
объяснения как обычного текста. Подмены действуют только внутри тестового браузера.

## Полный прогон

Существующие тесты остаются в своих каталогах; команда backend теперь также
обнаруживает новые сценарии в корневой папке `tests/`.

```sh
npm --prefix backend run lint
npm --prefix backend test
npm --prefix backend run build
npx --yes npm@11.6.2 --prefix frontend ci
npm --prefix frontend run lint
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend exec -- playwright install chromium
npm --prefix frontend run test:e2e
docker compose config --quiet
docker compose up -d --build --wait
node scripts/smoke.mjs
node scripts/browser-smoke.mjs
```

Для frontend используется npm 11.6.2, как в `frontend/Dockerfile`.
E2E запускает отдельный dev-сервер на порту 3101 с подменой API.
Smoke-проверки требуют работающие frontend на 3000 и backend на 3001;
браузерный smoke проверяет настоящее приложение на ширинах 1440, 390 и 320 px.
AI unit-тесты используют подмену SDK, а smoke без ключа проверяет fallback.
