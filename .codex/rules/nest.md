# NestJS

- Не лезть в потроха чужого модуля — только через опубликованный сервис/провайдер.
- Входящий DTO — только валидаторы. Исходящий DTO — каждое возвращаемое поле объявлено явно.
- Поле, которого нет в исходящем DTO, молча исчезает из ответа. Чинить в DTO, а не в запросе.
- `whitelist: true` режет поля, которых нет во входящем DTO; правя схему, обнови связанные DTO.
- Имена статусов результата держать в enum: `matched`, `no_category_in_city`, `no_candidates_after_filters`.
- Разбор CSV и scoring держать отдельно: loader нормализует данные, recommender ранжирует, explainer формирует объяснения.
- Детерминизм важнее случайной «умности»: tie-breaker должен быть стабильным, например score desc → price asc → id asc.
- Категории, форматы и языки парсить как списки через `|`; не сравнивать всю строку целиком.
- Даты занятости сравнивать как ISO `YYYY-MM-DD`; не использовать локализованные строки для логики.
- Тесты к recommender обязательны после scaffold: занятая дата, нет категории в городе, все кандидаты отфильтрованы, детерминированный порядок.
